# Resume Watchdog

長時間の作業では、usage limitによる中断から自動復帰できるようResume Watchdogを使用する。

## 実行時刻の決め方

Watchdogの実行時刻は、5時間枠の回復推定時刻の約5分後とする。

- `~/.claude/.sl_quota_start` に、ステータスラインスクリプト（`~/.claude/statusline.sh`）が推定した現在の5時間枠の開始時刻（Unix epoch秒）が入っている。🔄 に表示される残り時間と同じ値である。
- 回復推定時刻は「開始時刻 + 18000秒」。これが現在時刻より後なら、その5分後を実行時刻にする。
- ファイルがない、または回復推定時刻が現在時刻以前（枠が切れた後でまだ更新されていない）の場合は、現在時刻から5時間5分後を実行時刻にする。
- この値はAPIから得たものではなく推定である。本環境はAPIキー認証のため、ステータスラインの `rate_limits` は渡されず、429のエラー文にも回復時刻は含まれない。

## セッション開始時

実質的な作業を開始する前に `CronList` を確認する。

`WORK_RESUME_WATCHDOG` を含む有効なCronが存在しない場合、上記で決めた時刻に一度だけ実行されるone-shot Cronを `CronCreate` で作成する。

既に有効な `WORK_RESUME_WATCHDOG` が存在する場合は重複して作成しない。

## Watchdog発火時

`WORK_RESUME_WATCHDOG` が発火した場合、以下の順序で処理する。

1. 現在の作業が完了しているか確認する。
2. 完了している場合は何もせず終了し、新しいWatchdogも作成しない。
3. 未完了の場合、実質的な作業を再開する前に、上記で決めた時刻（発火時点で改めて `.sl_quota_start` を読む）のone-shot `WORK_RESUME_WATCHDOG` を作成する。
4. 会話履歴、現在のTodo・Plan、git status、git diff、直前のツールおよびサブエージェントの結果を確認し、中断地点を特定する。
5. usage limitなどによって失敗・中断したサブエージェントがあれば、必要に応じて再実行する。
6. 既に実行中のサブエージェントや同一作業を重複して開始しない。
7. ユーザーからの判断が本当に必要な場合を除き、確認を求めて停止せず、そのまま未完了作業を再開する。

## 原則

Resume Watchdogは通常の作業を妨げないセーフティネットとして扱う。

Watchdogを再帰的に継続する場合は、必ず「次のWatchdog登録」を「作業再開」より先に行う。

同一セッション内に複数の `WORK_RESUME_WATCHDOG` を作成しない。
